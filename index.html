Calsifer Twitch Overlay

We as a team got Desca as our client and she wanted a game for her chat to play while nothing interesting is happening during her stream. The key points are: to not take away too much of the stream, to be tailor made for Desca and to be something related to her beloved Calsifer.

After a lot of brainstorming we came up with tamagothci style game where Casifer is the chat's pet. We had a meeting and she liked the idea.

We split up into two teams: the artists and the coders. Later bacame the artists, the figma maniacs and the coder.

The architechture is the following:



Both the gui and overlay are hosted on a server running on localhost 3000. In order to start that server Desca will have to open a terminal inside the folder and type "npm install" to install all the dependancies once and then each time she wants to start the game she will have to open a terminal inside the server folder and type "node server". Then she will have to put the browser overlay inside obs with url "http://localhost:3000/overlay/index.html" and to access the gui she will have to go to "http://localhost:3000/gui/index.html" inside her own browser.

The server communicates to the gyi and overlay with a socket. The actuall commands comming from the chat are handled by streamer.bot where she can connect and modify how the viewer point redeems are handled. All of this is explained in the user guide.

The code is split into front and back. The front is on html and css and the back is in JavaScript.

S3MC-Patchwork Repository

In order to have a safe backup for our studio we desided to use GitLab.

The way we used it is that we have a two branch strategy where the main branch has a rule that forbids pushing and allows only merging and a side branch where everything is pushed. The idea is that we always have a safe branch where everything is backed up (a back up for the back up because I don't trust my team in their git skills).

The file stucture has archive with files that are not relevant anymore. This exists to eliminate unnessesary noise inside the repo. It also has prototypes folder with all the relevant prototypes that we are currently working on. There is also documents folder for documents. And the rest is part of the promotion webpage we made in order to attrackt Desca.





This is done because the people after us now can clone the repostory easily (if fontys transfer the repository to the actuall GitLab and not their own one) and have access to all documents and prototypes.

One of Chris and Dirk's feedback was that there is no README which as you can see in the pictures there is now explaining the file system and fix to a potential bug for the people that are to take the project after us. Bellow is a link to the repository.
