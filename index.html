Calsifer Twitch Overlay

We as a team got Desca as our client and she wanted a game for her chat to play while nothing interesting is happening during her stream. The key points are: to not take away too much of the stream, to be tailor made for Desca and to be something related to her beloved Calsifer.

After a lot of brainstorming we came up with tamagothci style game where Casifer is the chat's pet. We had a meeting and she liked the idea.

We split up into two teams: the artists and the coders. Later bacame the artists, the figma maniacs and the coder.

The architechture is the following:



Both the gui and overlay are hosted on a server running on localhost 3000. In order to start that server Desca will have to open a terminal inside the folder and type "npm install" to install all the dependancies once and then each time she wants to start the game she will have to open a terminal inside the server folder and type "node server". Then she will have to put the browser overlay inside obs with url "http://localhost:3000/overlay/index.html" and to access the gui she will have to go to "http://localhost:3000/gui/index.html" inside her own browser.

The server communicates to the gyi and overlay with a socket. The actuall commands comming from the chat are handled by streamer.bot where she can connect and modify how the viewer point redeems are handled. All of this is explained in the user guide.

The code is split into front and back. The front is on html and css and the back is in JavaScript.

S3MC-Patchwork Repository

In order to have a safe backup for our studio we desided to use GitLab.

The way we used it is that we have a two branch strategy where the main branch has a rule that forbids pushing and allows only merging and a side branch where everything is pushed. The idea is that we always have a safe branch where everything is backed up (a back up for the back up because I don't trust my team in their git skills).

The file stucture has archive with files that are not relevant anymore. This exists to eliminate unnessesary noise inside the repo. It also has prototypes folder with all the relevant prototypes that we are currently working on. There is also documents folder for documents. And the rest is part of the promotion webpage we made in order to attrackt Desca.





This is done because the people after us now can clone the repostory easily (if fontys transfer the repository to the actuall GitLab and not their own one) and have access to all documents and prototypes.

Game GUI

Because we wanted to make it easy for Desca to controll Calsifer we decided to make a GUI.

Me, Constantin and Dylan used the diamond method and did it in FIgma. I asked to use Figma because I wanted to practice it more since it is what I wanted to lean the most this semester.

Constantin did the low fidelity that was liked by Dylan but I didn't really like how many tabs there were and how spread out everything was. So I wanted to make a simpler GUI where everything is closer together and a preview of Calsifer is also there. My reasoning was that because Desca was going to be straming she would spend too much time searching for specific things to change on Cal. where she might end up giving the GUI more attention than the strean itself. This would also reduce tiredness cause by search fatigue. I made a applied research document explaining why reducing search fatigue is important. You can fing it here.

I tried looking online and found a GUI that was a really close mathc to what I wanted and tried copying the layout. Since I have no idea how to position stuff I decided to copy completely the control panel and character's position.



I learned how to use the measurment tool in order to make a complete cope so it doesn't seem off.

Then I did the same for the control panel because I really liked the layout of the inspiration I found.



After that I felt that the space was a bit too empty so I added some more stuff. The "Create Character" textbox was copied but I instead decided to name is "Calsifer Configuration". I copied the footer but instead of using it as info box I wanted to use it as a textbox where Desca can add text to Calsifer. I also copied the scroll in the controll panel but because I needed a way to display how much HP Cal. has curretly I decided to use it as HP bar.



Next my team told me that now the space above Cal. looks empty. This isn't the case for the inpiration GUI becaise of the backgorund textures and that the character is taller. For that I decided to add a language dropbox on the position where you would usually find one. I copied one from an online picture I found. I also added text above Cal. so that space isn't so empty. Then I filled out the text and switched to swipe bars on the health and hunger sections since it's gonna make adjusting that easier.



I got feedback from Wouter that was that maybe I can do more styling to the buttons and have an interesting background. He also pointed that I did not do a low fidelity sketch which I will try and do next time.

I tried doing some styling myself where I added shadows to the things that are ment to be pressable, some colors and icons to the health and hunger swipe bars. I wanted to make it easy to recognise the health and hunger and there doesn't exist a better solution than adding the minecraft icons and colors. I also changed the title to Calsifer following the "How's Moving Castle" font.



After we had a meeting with Desca on feedback. She completely ignored the functionable and being easy on her part and went for the prettier more chaotic design that Constantin made. I don't really blame her, my design wasn't really ment to be pretty.



Afterwards Dylan and Constantin continued working on the design while I started coding. The original plan was that I would start coding and then they would join me but for whatever reason they finished the Figma work about a month late and did no code work. The final GUI is not coded.

I entirely blame myself for this because I was the scrum master and was not hard enough on them. The reason is that forgot about the scrum workflow and being the scrum master because I got scared from Dirk and Chris' feedback and started working more individually. Key point is that I should have stayed more consistent with giving out tasks and managing the team.
